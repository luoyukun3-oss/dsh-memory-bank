# 知识页写入格式规范

> 给**替你写记忆的助手**看的。你自己手写 Markdown 也适用。
>
> **先说结论：写错格式不会让系统崩。** 实测 12 种坏格式（未闭合注释、非法值、字段名拼错、
> TOC 缺半边、表格缺列、20 万字符单行、空文件、全角列表…）—— `reindex` / `recall` / `bootstrap`
> **全部照常返回，一次都没抛错**。
>
> 所以真正的代价不是崩溃，是**静默失效**：你以为记下了 `i:5`（最高重要度），实际它被忽略了；
> 你以为元数据注释不影响正文，实际那串 `<!-- i:5 -->` 已经混进检索文本。下面是实测出来的边界。

---

## 一、元数据注释（唯一容易写错的地方）

写在**条目行尾**，成对包起来：

```markdown
- 某条内容 <!-- i:5 s:user c:high -->
```

| 字段 | 含义 | 合法值 | 写错会怎样（实测） |
|---|---|---|---|
| `i` | 重要度 | **1–5 的整数** | `i:99` ⇒ **整条元数据作废**（不是当成 99） |
| `s` | 来源 | `user` / `probe` / `infer` | 非法值 ⇒ 该字段被丢 |
| `c` | 置信度 | `high` / `mid` / `low` | 同上 |
| `x` | 到期日 | `YYYY-MM-DD` | 格式错 ⇒ 该字段被丢 |
| `sup` | 被谁取代 | 任意文本 | — |
| `pin` | 引脚固定 | `1` | — |
| `t` | 主题标签 | 逗号分隔 | — |
| `cue` | 触发词 | 逗号分隔，**别用空格** | 带空格会被当成独立词 |
| `rel` | 关联边 | `rel:页:关键词[:类型]` | 指向不存在的页 ⇒ 死边（不崩，`cli lines` 只报数） |

### 三条硬规则

1. **必须成对**：`<!-- ... -->`。只写开头的 `<!--` ⇒
   **元数据全丢，而且那串注释留在正文里**（实测 `parseMeta` 返回 `{meta:{}, 正文仍含 "<!-- i:5 s:user"}`）
   ⇒ 它会进索引、进注入，白占预算。
2. **字段名必须在白名单里**。拼错（如 `im:5`）⇒ **静默忽略**，不报错、不提示。
3. **一行只能有一条注释**。写在中间（不在行尾）会被当正文。

## 二、条目行

```markdown
- 条目正文            ← 只认半角 `- ` 或 `* ` 开头
  缩进续行属于上一条   ← 两个空格以上缩进
- 下一条
```

| 写法 | 会被识别成什么（实测） |
|---|---|
| `- xxx` / `* xxx` | ✅ 一条 |
| `  xxx`（缩进续行） | ✅ 归到上一条正文（**不是**独立条目） |
| `－ xxx`（全角减号） | ❌ 不是条目，只算普通正文 |
| `• xxx`（项目符号） | ❌ 不是条目 |
| `1. xxx`（有序列表） | ❌ 不是条目 |

**章节**用 `##` 切：同一 `##` 下的条目归一组，组名会进索引标题。

## 三、特殊页的要求

| 页 | 要求 | 写错的后果 |
|---|---|---|
| `faults.md` | 用**表格**（`| 症状 | 先查这里 |`），一行一个故障 | 缺列 ⇒ 那条标题只剩首格，仍能检索但可读性差 |
| `todos.md` | 顶部可有 `<!-- TOC:BEGIN -->…<!-- TOC:END -->` 块（由 `tools/page-toc.mjs` 生成，**别手写**） | 缺 `END` ⇒ TOC 不生效，回退逐条索引（不崩） |
| `aliases.md` | 一行一组，`|` 分隔，**术语放第一个** | 组太少会降低同义召回 |
| `inbox.md` / `handoff.md` | 不进召回，随便写也不污染检索 | — |
| `todos-archive.md` | 归档页不建索引 | — |
| `decisions.md` / `events.md` | 每条带日期前缀，便于按时间筛 | 无日期 ⇒ 算不出年龄，哑弹审计会跳过它（宁漏勿杀） |

### ⚠️ `events.md` 有一条**必须遵守**的规则（实测会静默丢光）

`cli ev import` 把 `events.md` 导进 SQLite 时，**必须先有一个 `## YYYY-MM-DD` 章节头**，
否则 `day` 为 null、**所有条目被静默跳过**（不报错、不警告，只告诉你「0 条事件」）：

```markdown
# events（事件叙事）

## 2026-11-08          ← 必须有。只写一级标题 `# events` 不行

- 2026-11-08 【第一次跑通】装好记忆银行，先记一条事件试试。
- 2026-11-08 【写第二条】验证事件能进库。
```

实测对照：同两份内容，**没有 `##` 节 ⇒ 导入 0 条；加上 ⇒ 导入 2 条**。
条目正文里再写一遍日期是允许的（解析器会用它覆盖节头日期，见 `parseEventsMd` 的注释）——
它存在的原因是历史数据只有一个日期节、真实日期写在正文开头。

> 记住这条的通用教训：**导入类命令的「0 条」通常不是没数据，是格式没匹配上。**
> 看到 0 条先去查解析规则，别怀疑自己没写内容。

## 四、写完必须验证

```bash
# ① 重新索引（改了源文件不 reindex，检索看到的还是旧内容）
node <bank>/cli.mjs init          # 或对单页：tools/reindex-page.mjs <页>

# ② 看注入有没有真的带上它
node <bank>/cli.mjs preview

# ③ 确认能被召回
node <bank>/cli.mjs recall "关键词"

# ④ 全量自检（含行数预算、TOC 一致性）
node <bank>/test.mjs
```

**别只靠「文件写出去了」判断成功** —— 上面第 ① 步是最常忘的：`tick` 会刷新索引，
但你手动改完不等 `tick` 就跑 `recall`，看到的是**旧结果**。

## 五、给助手的额外提醒（踩过的坑）

- **写新待办别往页尾追加**：`todos.md` 的注入配额超限时**从尾部整条切掉**，
  追加到末尾 = 第一个被挤掉。要插到「## 进行中」节首。
- **想藏细节就用 `> ` 引用块**：引用块行不进注入、不进索引。
- **`<!-- -->` 不能用来藏内容**：索引会跳过 `<` 开头的**单行**，但**不跳过区间** ——
  多行注释中间的内容照样会被读到。
- **别用模板字符串拼这些内容**（如果你在写脚本）：正文里的裸反引号会让脚本在解析阶段就崩，
  一行都执行不了。用单引号数组 `join`。
